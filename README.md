# Мониторинг света через Xiaomi Robot Vacuum E5

GitHub Actions раз в минуту проверяет в Xiaomi Cloud, онлайн ли робот-пылесос. Если он офлайн дольше порога (по умолчанию 5 мин), бот пишет в Telegram «❌ Света нет», а когда робот вернётся онлайн — «✅ Свет есть» с длительностью отключения.

Файлы:
- `watchdog.py`, `.github/workflows/watchdog.yml`: сторож, проверяющий, что мониторинг работает;
- `monitor.py`: скрипт (`login` запускается локально, `check` — в Actions);
- `.github/workflows/monitor.yml`: расписание и ручной запуск;
- состояние (`state.json`) хранится в `actions/cache`, в репозиторий не коммитится.

## 1. Репозиторий: публичный, не приватный

Workflow работает почти круглосуточно (~43 000 мин/мес). В приватном репо бесплатно только 2000 мин/мес, в **публичном** минуты для стандартных раннеров не ограничены. Секреты в публичном репо остаются скрытыми.

Создай репозиторий на github.com и загрузи в него содержимое этой папки.

## 2. Telegram-бот

1. В Telegram открой **@BotFather** → `/newbot` → придумай имя → получишь токен вида `123456:ABC...`. Это `TELEGRAM_BOT_TOKEN`.
2. Напиши своему боту любое сообщение (иначе он не сможет тебе писать).
3. Открой в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найди `"chat":{"id":123456789`. Это `TELEGRAM_CHAT_ID`. Можно проще: написать **@userinfobot**, он пришлёт твой ID.

## 3. Токены Xiaomi, регион и ID пылесоса (локально, один раз)

Xiaomi почти наверняка потребует подтверждение входа с серверов GitHub. Поэтому входим **с домашнего компьютера** и кладём в секреты уже готовые сессионные токены.

```bash
pip install -r requirements.txt
python monitor.py login
```

Скрипт спросит логин и пароль Xiaomi. Если Xiaomi попросит капчу, откроется картинка: перепечатай символы с учётом регистра. Если придёт код на почту аккаунта, введи его. Затем скрипт:
- переберёт регионы (`de`, `ru`, `cn`, `us`, …) и покажет устройства с их `did`, моделью и статусом online/OFFLINE;
- выведет `XIAOMI_USER_ID`, `XIAOMI_SSECURITY`, `XIAOMI_SERVICE_TOKEN` и найденный регион.

`did` пылесоса из списка — это `XIAOMI_DEVICE_ID`.

## 4. Секреты и переменные в GitHub

Репозиторий → **Settings → Secrets and variables → Actions**.

**Secrets** (вкладка *Secrets* → *New repository secret*):

| Имя | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен от @BotFather |
| `TELEGRAM_CHAT_ID` | твой chat ID |
| `XIAOMI_USER_ID` | из `monitor.py login` |
| `XIAOMI_SSECURITY` | из `monitor.py login` |
| `XIAOMI_SERVICE_TOKEN` | из `monitor.py login` |
| `XIAOMI_REGION` | из `monitor.py login` (например `de` или `ru`) |
| `XIAOMI_DEVICE_ID` | `did` пылесоса |
| `XIAOMI_USERNAME`, `XIAOMI_PASSWORD` | *необязательно*: запасной вход, если токены протухнут |

**Variables** (вкладка *Variables*, всё необязательно):

| Имя | По умолчанию | Смысл |
|---|---|---|
| `OFFLINE_THRESHOLD_MIN` | `5` | сколько минут робот должен быть офлайн до уведомления |
| `TIMEZONE` | `Europe/Moscow` (UTC+3) | часовой пояс для времени в сообщениях и сводках |
| `SUMMARY_HOUR` | `21` | в котором часу присылать сводки |
| `SUMMARY_WEEKDAY` | `6` | день недельной сводки (0 — пн … 6 — вс) |

## 5. Тестовый запуск

**Actions → Power monitor → Run workflow**, поставь галочку «Только тест». Тест только присылает текущий статус и не мешает основному циклу. В Telegram должно прийти `🔧 Тест мониторинга — «…»: онлайн — свет есть`. Если что-то не так, ошибка придёт туда же и будет в логе шага *Check*.

Потом запусти **Run workflow** ещё раз без галочки — начнётся цикл, дальше его подхватит cron.

После этого всё работает само по расписанию. Если в Actions появилась плашка про включение workflows, нажми **Enable**.

## 6. Сторожа: уведомление, если мониторинг перестал работать

**Встроенный сторож (работает сам, настраивать не нужно).** Отдельный workflow `Watchdog` раз в ~30 мин проверяет через GitHub API, что «Power monitor» включён и запускается. Если workflow отключён или не запускался дольше 30 мин, бот пришлёт «⚠️ Сторож: мониторинг света не работает», а после восстановления — «✅». Ограничение: если GitHub отключит Actions во всём репозитории или аккаунте, встроенный сторож тоже замолчит.

**Внешний сторож (необязательно, healthchecks.io).** Закрывает и этот случай: скрипт каждую минуту шлёт отметку на внешний сервис, а если отметок нет 15 мин, сервис сам пишет в Telegram.

1. Зарегистрируйся на https://healthchecks.io (бесплатно). Если письмо не пришло, проверь «Спам» и «Промоакции».
2. **Integrations → Telegram → Add Integration** → в `@HealthchecksBot` нажми Start.
3. Открой проверку → **Change Schedule**: Period = 1 minute, Grace Time = 15 minutes → Save.
4. Скопируй ping URL (`https://hc-ping.com/…`) и добавь его в GitHub как секрет `HEALTHCHECK_URL`.

## Как это себя ведёт

- **Сводки.** Каждый день в 21:00 приходит сводка за последние сутки (с 21:00 вчера до 21:00): сколько было отключений, сколько не было света, список интервалов. По воскресеньям в 21:00 дополнительно приходит сводка за неделю с разбивкой по суткам. Если в 21:00 света нет, сводки ждут: они придут сразу после «✅ Свет есть» и включат это отключение целиком, а следующая сводка начнётся с момента возвращения света. История хранится 40 дней. Тестовый запуск присылает сводку за последние 24 ч.
- **Кнопки в чате.** Внизу чата постоянные кнопки «📊 Сутки» (последние 24 ч), «📅 Неделя» (последние 7 дней по суткам) и «💡 Статус». То же доступно командами `/day`, `/week`, `/status`. Бот отвечает только на сообщения из `TELEGRAM_CHAT_ID`. Между долгими запусками (1–2 мин) ответ может задержаться.
- **Закреплённое сообщение** вверху чата показывает, сколько уже есть или нет света, и обновляется раз в минуту. Если его удалить, бот создаст и закрепит новое.
- **Короткие сбои Wi-Fi** короче порога не дают уведомлений.
- **Как устроен цикл.** Один запуск проверяет статус раз в минуту ~5 ч 45 мин. В самом начале он сам ставит в очередь следующий запуск, и тот стартует сразу после окончания текущего. Cron раз в 30 мин — запасной вариант, если цепочка оборвётся (сам по себе GitHub запускает cron нерегулярно, с пропусками до часа и больше). Паузы между запусками — 1–2 мин на подготовку.
- **Задержка уведомления** ≈ сколько Xiaomi Cloud замечает офлайн (обычно несколько минут) + порог + до 1 мин.
- **Сбой проверки** (Xiaomi недоступен и т.п.) 3 раза подряд (~3 мин) → одно предупреждение «⚠️ Мониторинг не может проверить статус», после восстановления — «✅ снова работает».
- **Токены протухли:** скрипт попробует войти по паролю (если он задан, не чаще раза в час). Если Xiaomi требует подтверждение, придёт предупреждение. Тогда снова запусти `python monitor.py login` локально и обнови три секрета `XIAOMI_*` с токенами.
- **Не уходит сообщение в Telegram:** состояние не сдвигается, и уведомление повторится при следующем запуске.
- **60 дней без коммитов:** GitHub отключает cron в публичных репо. Workflow сам делает пустой коммит `keepalive` раз в ~50 дней.

## Риски

Правила GitHub предполагают, что Actions используются для работы над кодом, а не как круглосуточный сервер. GitHub может отключить такой workflow. Тогда можно вернуться к редкому cron: `--loop-minutes 0` и `cron: "*/5 * * * *"`.

API Xiaomi неофициальный (протокол как у Xiaomi-cloud-tokens-extractor) и может сломаться. Тогда придёт предупреждение о сбое проверки.
